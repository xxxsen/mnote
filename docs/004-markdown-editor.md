# Markdown 双栏编辑页面

## 1. 功能范围

`/docs/[id]` 是文档编辑主页面。它同时承担 Markdown 源码编辑、实时预览、本地草稿、远端保存、标签、AI 辅助、文件粘贴、文档关联、历史版本和分享入口。编辑器的首要目标是避免内容丢失和旧请求覆盖新内容。

## 2. 数据加载与初始化

页面路由先取得文档 ID，客户端加载当前文档详情、标签、摘要、分享状态和关联信息。后端详情查询必须同时校验用户归属。

初始化时区分三份内容：

- 服务端已确认内容：最近一次远端读取或保存成功的正文。
- 当前编辑内容：CodeMirror 中的即时内容。
- 本地草稿：浏览器为该文档保存的未确认内容。

草稿 Key 为 `mnote:draft:{documentId}`，值包含内容和更新时间。当前实现会在草稿正文非空且与服务端正文不同时自动把草稿作为当前编辑内容，并标记为未保存；页面没有恢复确认步骤。该行为优先保护未提交编辑，但无法判断草稿是否比远端更新。修改加载策略时应比较可用版本信息或增加用户确认，不能直接删除草稿。

## 3. 双栏编辑

- 左栏是 CodeMirror Markdown 源码编辑器。
- 右栏是 Markdown 实时预览。
- 预览内容在输入后短暂防抖更新，避免每个按键触发完整渲染。
- 字符数、词数和脏状态随当前内容更新。
- 两栏滚动采用百分比映射同步，用户主动滚动一侧时驱动另一侧，程序更新不能形成往返循环。

桌面端以固定双栏为主。窄屏布局必须保留编辑和预览的可达性，不能因浮层遮挡保存状态或主要操作。

## 4. 标题与正文

编辑器从 Markdown 正文第一条非空行推导标题，并把标题和正文一起保存：ATX 一级标题去除 `# `；下一行仅由 `=` 组成时按 Setext 标题处理；其他首行直接作为标题，超过 50 个字符时截断并追加省略号。创建后的 `Untitled` 只是占位值；正文没有非空行时不发起保存。

标题解析规则属于持久化契约。修改 Markdown 标题识别时，必须同时检查：

- 编辑器顶部标题展示。
- 保存请求中的标题。
- 文档列表和模板创建后的标题。
- 版本对比中的标题差异。
- 导出和公开分享中的标题。

## 5. 本地草稿

- 当前内容变脏后，页面按短延迟写入本地草稿。
- 页面卸载且仍有未确认修改时保留草稿。
- 只有远端已确认内容与当前最新编辑内容一致时才能清除草稿。
- 保存请求成功但编辑器在请求期间又发生修改时，不能清除新草稿。
- 当前草稿加载只接受 truthy 的 `content`，因此“删除到空正文后崩溃或刷新”不会从空草稿恢复，这是已知数据保护缺口。修复时必须把“字段存在”与“正文非空”分开判断。

浏览器存储失败、配额不足或 JSON 损坏时，页面应降级并提示，不应阻止继续编辑。

## 6. 保存队列与并发

前端保存状态包括同步、保存中、已排队和失败。保存机制遵循单在途、最新值优先：

1. 用户触发保存或自动保存。
2. 若没有在途请求，发送当前标题、正文和递增 `save_seq`。
3. 若已有请求，只记录最新待保存快照，不并发发送多份正文。
4. 当前请求结束后，如果仍有更新，立即发送最新快照。
5. 后端只接受大于当前内容修订号的保存序号，并在响应中返回是否接受及当前修订号。
6. 未接受的旧保存不能被前端显示为“已同步”，前端应快进序号并继续保存最新内容。

自动保存按固定间隔触发，只在内容与最近确认内容不一致且标题有效时运行。手动保存与自动保存共享同一个队列，不能各自建立并发通道。

后端在事务中锁定文档记录，保存正文、版本、关系和异步处理状态。任何绕过 `save_seq` 的写入路径都可能破坏最新写入优先规则。

## 7. 编辑辅助

编辑器提供以下源码级能力：

- Markdown 行内和块级格式工具栏。
- 表格、Emoji、文字颜色和字号插入。
- 编辑器主题切换和本地记忆。
- `/` 命令菜单。
- `[[` 文档搜索并插入内部链接。
- `#` 标签建议。
- `Ctrl/Cmd + K` 快速打开文档。
- 列表换行自动延续。
- Go fenced code block 内的关键字、内置标识、包和当前代码标识补全。
- 撤销和重做。

插入操作必须基于 CodeMirror 当前 selection 和 transaction，不能直接修改 React 字符串导致光标、撤销栈或输入法状态丢失。

## 8. 文件粘贴与上传

粘贴文件时先插入本地占位，异步上传成功后按 MIME 类型替换为图片、视频、音频或普通文件 Markdown。约束如下：

- 上传中同一占位只被对应请求替换。
- 上传失败保留可识别的失败状态并允许重试或删除。
- 用户在上传期间编辑附近文本时，不能按旧字符偏移覆盖新内容。
- 后端返回的 URL 是最终引用事实源，前端不能自行猜测存储路径。

## 9. 标签与文档关系

编辑器允许查询和维护当前文档标签，并限制页面选择数量和标签格式。标签更新使用独立接口并由后端事务替换文档标签关系。

正文保存也会触发链接和资产引用重建：

- 内部文档链接形成出链和反向链接数据。
- 文件 URL 形成文档资产关系。
- 关系重建必须与正文保存位于同一事务。

正文保存请求和标签更新请求的字段语义必须保持明确。若保存 DTO 把缺失的 `tag_ids` 解释为空列表，调用方可能意外清空标签；新增调用方必须显式遵守后端当前契约或先修改为可区分“未提供”和“清空”的模型。

## 10. 侧栏与浮动面板

页面提供摘要、版本、分享、目录、反向链接、出链和相似文档等辅助信息：

- 摘要可以由用户编辑或由 AI 生成后应用。
- 版本入口跳转到专用恢复页。
- 分享面板维护权限、密码、有效期和下载开关。
- 目录从当前预览标题生成。
- 反向链接和出链来自持久化关系。
- 相似文档按标题延迟查询并排除当前文档。

浮动面板折叠状态保存在本地。辅助请求失败不能阻止正文编辑和保存。

## 11. 离开页面与删除

离开页面前应优先提交最新待保存内容；无法确认保存时保留本地草稿。删除文档需要二次确认，成功后清理当前文档草稿并返回文档库。删除由后端软删除或状态更新实现，相关用户查询不再返回该文档。

## 12. 不可破坏的约束

- 任何旧请求都不能覆盖较新的编辑内容。
- 草稿只能在“服务端确认了当前最新内容”后清理。
- 输入法 composition 期间不能触发破坏中文输入的快捷操作。
- 编辑器 transaction、selection 和 undo history 必须由 CodeMirror 管理。
- 内容保存必须同步维护版本、链接、资产关系和向量待处理状态。
- AI、摘要、相似文档、分享等辅助能力失败时，正文编辑仍可用。
- 内部链接、资产 URL 和标题语法变化属于跨模块契约，不能局部修改。

## 13. 验证要点

- 加载、编辑、自动保存、手动保存、刷新后内容一致。
- 慢请求期间连续输入，最终远端内容为最后一次编辑。
- 保存失败、断网、关闭页面和重新打开时草稿可恢复。
- 输入法、撤销重做、快捷键、粘贴上传和滚动同步互不干扰。
- 标签、链接、资产和版本在保存后与正文一致。
- AI 或分享接口失败不影响编辑和再次保存。
