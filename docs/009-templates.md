# 模板页面与文档创建

## 1. 功能范围

`/templates` 用于维护可复用 Markdown 模板，并通过变量替换创建新文档。模板包含名称、描述、正文和默认标签。模板是当前用户私有资源。

## 2. 页面结构

页面左侧展示模板元数据列表，右侧展示和编辑选中模板：

- 列表按服务端分页加载。
- 搜索在当前已加载列表中筛选；若改为服务端搜索，必须明确分页语义。
- 选中模板后再加载完整正文和默认标签。
- 新建、编辑、删除和使用模板共享当前选中状态。

切换模板前若存在未保存修改，页面应阻止静默丢失或先让用户确认。

## 3. 模板数据

- 名称在同一用户下唯一。
- 描述用于列表说明。
- 正文保存 Markdown 原文和变量占位。
- 默认标签保存当前用户标签 ID。
- 创建和更新时间用于排序和 UI 状态。

名称唯一性由数据库约束兜底。并发保存同名模板时返回归一化冲突，而不是覆盖其他模板。

## 4. 变量语法

变量使用 `{{KEY}}`，Key 规范化为大写。支持两类变量：

- 用户变量：从正文中提取，使用模板时由用户填写。
- 系统变量：`SYS:TODAY`、`SYS:DATE`、`SYS:TIME`、`SYS:DATETIME` 和 `SYS:NOW`，由后端按服务器配置时区生成。

替换规则必须稳定：

- 同一 Key 的多次出现使用同一个值。
- 未提供或未知变量使用明确的空值规则。
- 变量只做文本替换，不执行表达式或模板代码。
- 大小写规范化在提取和替换阶段一致。

若系统需要用户时区，应把时区作为显式账户配置传递，不能依赖浏览器和服务器碰巧处于同一时区。

## 5. 新建和编辑模板

表单保存期间禁用重复提交。默认标签选择遵循标签所有权和数量限制。后端写入前再次校验所有标签，不信任前端传入的 ID。

编辑接口只允许修改当前用户的模板。部分更新与完整替换必须有清晰 DTO，避免缺失字段把正文或标签清空。

## 6. 使用模板创建文档

如果当前模板有未保存修改，页面先保存模板，成功后再打开变量填写流程。创建流程如下：

1. 前端提取需要填写的用户变量。
2. 用户填写变量并可指定文档标题。
3. 后端重新读取模板，使用服务端模板正文作为事实源。
4. 后端替换用户变量和系统变量。
5. 校验默认标签仍属于当前用户并去重。
6. 在文档创建流程中写入正文、初始版本和标签。
7. 返回新文档 ID，页面跳转编辑器。

标题优先使用用户显式输入；否则从渲染后正文第一条有效内容推导并去除 Markdown 标题标记，最后退回模板名称或 `Untitled`。

## 7. 删除

删除模板需要确认，不影响已经由模板创建的文档。后端按用户和模板 ID 删除。当前选中模板删除后，页面选择相邻项或进入空状态。

## 8. 接口契约注意事项

模板创建文档请求中的变量值和标题是有效输入。若存在前端预览内容字段，后端不应信任它作为最终正文，以防旧模板或被篡改内容绕过服务端变量解析。无效或未使用字段应从契约中移除，避免调用方产生错误预期。

## 9. 不可破坏的约束

- 模板名称唯一范围是当前用户。
- 服务端模板正文是创建文档的事实源。
- 变量只做受控文本替换，不执行代码。
- 默认标签必须在创建文档时重新验证所有权。
- 模板删除不影响既有文档。
- 使用未保存模板时必须先确认保存成功。
- 创建文档必须复用正式文档创建事务，而不是拼接多次独立写入。

## 10. 验证要点

- 新建、修改、切换和删除模板不会丢失未保存内容。
- 同名冲突和并发创建返回稳定错误。
- 重复变量、未知变量、空值和所有系统变量替换一致。
- 默认标签被删除或越权时不会形成无效关系。
- 未保存模板使用流程先保存再创建。
- 由模板创建的文档具有正确标题、正文、初始版本和标签。
