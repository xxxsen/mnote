# 后台任务与调度

## 1. 功能范围

后台调度负责文档向量、自动摘要、缓存清理和导入暂存清理。任务在 HTTP 服务进程内运行，使用数据库状态作为可恢复事实源。任务失败不能破坏请求线程已提交的业务数据。

## 2. 生命周期

服务启动完成依赖初始化后注册定时任务，调度器开始运行。服务关闭时：

1. 停止接受新调度。
2. 等待或取消可安全中断的任务。
3. 释放数据库、存储和 Provider 资源。

任务使用服务级上下文。由导入确认启动的后台执行使用脱离单次 HTTP 请求取消信号的上下文，但仍应响应服务关闭。

## 3. 向量任务

向量扫描按分钟级周期运行，批量领取 pending 或租约过期的文档：

- 使用原子状态更新取得处理权。
- processing 状态带租约时间。
- 调用分块和 Embedding 前读取当前内容哈希。
- 写入前重新检查哈希。
- 成功标记 complete。
- 失败记录错误、重试次数和下一次时间，并指数退避。

任务需限制单批数量和外部并发，避免 Provider 限流或数据库连接耗尽。多个服务实例运行时，数据库领取条件保证同一文档不会被正常并发处理。

## 4. 自动摘要任务

摘要任务每分钟扫描摘要缺失，或 `documents.mtime` 晚于 `document_summaries.mtime`，且正文已稳定超过配置延迟的文档，单批最多处理有限数量。它顺序调用摘要 Provider 并写入摘要时间，不改变文档正文和更新时间；AI 未配置时直接跳过。

当前摘要记录没有源内容哈希、记录租约或提交时 compare-and-swap。生成期间正文变化时，旧摘要可能覆盖新内容对应的摘要；多实例也可能领取同一候选文档。这是当前实现边界，后续修复应为摘要保存源修订或内容哈希，并在提交时原子校验。

## 5. 缓存清理

缓存清理按日运行，删除超过保留期的数据库缓存记录。进程内 LRU 自行按 TTL 淘汰。

清理查询应分批，避免长事务和大范围锁。缓存删除不影响主数据；后续请求可以重新生成。

## 6. 导入清理

导入清理按小时运行，删除超过保留时间的已完成、失败或未确认任务及暂存数据。运行中任务和仍在有效预览期内的任务不得被删除。

父任务和暂存记录按事务或明确级联顺序删除，不能留下孤儿暂存。

## 7. 重叠和多实例

同一进程内的定时任务应避免前一轮未结束时重叠启动。跨实例互斥不能只依赖进程内锁，必须通过数据库领取、租约、advisory lock 或幂等清理条件实现。

各任务采用不同保护策略：

- 向量：按记录租约和内容哈希提交保护。
- 摘要：仅有每个进程内的调度防重叠，当前没有跨实例记录租约。
- 导入：任务状态条件更新。
- 清理：按过期条件幂等删除。

## 8. 可观测性

日志记录任务名称、批次 ID、扫描数量、成功/失败数量、耗时和归一化错误。不得记录完整文档正文、Prompt、Provider 密钥或验证码。

永久失败和连续重试应可被运维发现。单条数据错误不应让整批任务退出，除非数据库或配置处于系统性不可用状态。

## 9. 不可破坏的约束

- 后台任务不在用户请求事务中调用长时间外部服务。
- 向量任务提交结果前检查内容哈希；摘要任务当前缺少同等级保护，修改摘要流程时必须补齐。
- 服务重启后租约过期任务可以恢复。
- 同一记录的并发处理通过数据库状态协调。
- 清理任务只删除可再生成或明确过期的数据。
- 任务停止和服务关闭有确定的取消边界。
- AI 失败不影响正文保存和读取。

## 10. 验证要点

- 正常周期可以领取、处理并更新状态。
- 向量 Provider 失败触发持久化退避，不形成热循环；摘要错误按当前批处理规则记录和短暂冷却。
- 向量处理期间正文变化时旧结果被丢弃。
- 向量进程崩溃后租约过期记录可重新处理。
- 多实例下向量领取保持互斥；摘要的重复领取和过期结果作为已知边界被监控。
- 清理任务不会删除运行中任务或主业务数据。
- 服务关闭后不再启动新任务，已有任务按约定结束。
