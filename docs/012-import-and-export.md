# 导入、导出与数据交换

## 1. 功能范围

系统支持从 HedgeDoc Markdown ZIP 和 Notes JSON ZIP 导入，并支持完整 JSON、Notes ZIP 和 Confluence HTML 导出。导入采用“上传解析、预览、确认、后台执行、状态轮询”流程，避免未确认数据直接写入正式文档。

## 2. 导入任务生命周期

导入任务状态按以下阶段变化：

1. 上传：接收 ZIP 并校验整体大小。
2. 解析：逐条解析为暂存记录，统计标题冲突和标签。
3. 预览：返回汇总、冲突信息和有限样例。
4. 确认：用户选择冲突策略，后端以条件更新把任务从待确认切到运行中。
5. 执行：后台协程逐条写入正式文档。
6. 完成或失败：保存最终计数、错误摘要和进度。

确认操作必须幂等。只有一次状态转换可以启动后台执行，快速重复点击不能创建两个导入协程。

## 3. HedgeDoc 导入

HedgeDoc ZIP 读取 `.md` 文件：

- 文件名用于初始标题。
- 正文保留 Markdown。
- 识别并移除 HedgeDoc 标签尾行，如 `###### tags:`。
- 标签名称转换为当前用户标签。
- ZIP 内重复标题先形成可区分名称，避免同批数据互相覆盖。

解析器必须防 ZIP 路径穿越、压缩炸弹、过大单文件和过多条目。非 Markdown 文件被忽略或计入明确告警。

## 4. Notes 导入

Notes ZIP 读取 `.json` 文件，支持标题、正文、摘要和标签列表。约束包括：

- 每条记录有大小上限。
- 总条数有上限。
- 正式执行前再次校验必填正文和解析结果。
- 未知字段被忽略，类型错误形成可定位的条目错误。

暂存数据按任务和用户隔离。知道任务 ID 的其他用户不能预览、确认或查询状态。

## 5. 冲突策略

用户确认时选择：

- `skip`：目标标题已存在时跳过。
- `overwrite`：更新已有文档。
- `append`：保留已有文档，为新文档标题添加递增后缀。

默认策略是追加。覆盖模式调用统一 `DocumentService.Update`，不提供 `BaseRevision`，由服务端在文档行锁内把当前修订号递增 1，并生成版本、替换标签、重建链接和资产关系、标记向量待处理。无基准写入只允许已经完成覆盖决策的服务端导入流程使用；HTTP 编辑接口必须提供基准修订。

## 6. 后台执行与进度

确认后使用脱离原 HTTP 请求取消信号的后台上下文执行，因此前端离开或网络断开不会取消已确认任务。任务定期写入进度，最终保存成功、跳过、失败计数和有限错误详情。

前端轮询状态时：

- 使用固定短间隔。
- 完成或失败后停止。
- 达到前端等待上限后提示用户稍后查询，不把任务标记失败。
- 组件卸载后清理定时器和请求。

后台任务必须允许单条失败后继续处理其余记录，并保证每条正式写入自身事务完整。

## 7. 暂存清理

定时任务清理超过保留时间的导入任务和暂存记录。运行中任务不能被清理。清理需要覆盖失败和用户未确认的历史任务，避免数据库无限增长。

## 8. 完整 JSON 导出

完整导出返回用户数据快照，包括文档、版本、标签和文档标签关系。导出查询必须按用户过滤，并保持关系可恢复所需标识。

它是数据备份格式，不应混入临时 UI 状态、JWT、OAuth Token、密码摘要或存储凭证。

## 9. Notes ZIP 导出

Notes 导出为 ZIP，每篇文档一个 JSON 文件，包含标题、正文、摘要和标签列表。文件名使用稳定安全的生成方式，避免同名覆盖和路径注入。

导出过程中使用临时文件时，成功、失败和请求取消都必须清理。大数据量应流式输出或设置资源上限，避免把整个 ZIP 常驻内存。

## 10. Confluence HTML 导出

单文档 Confluence 导出把 Markdown 转换为兼容 HTML。接口需要文档 ID 和当前用户鉴权。转换失败只影响当前导出，不修改原文档。

Markdown 扩展不一定能在 Confluence 中等价表示；不支持结构应降级为可读文本或代码块，而不是丢失内容。

## 11. 不可破坏的约束

- 上传解析不直接写正式文档，必须经过用户确认。
- 任务状态转换原子且确认幂等。
- 暂存、状态和正式数据都按用户隔离。
- 覆盖导入必须遵守文档版本和并发写入协议。
- 单条失败不破坏其他条目，也不留下半写关系。
- ZIP 处理必须限制总大小、条目数、单条大小和解压路径。
- 所有导出排除认证凭据和内部密钥。
- 临时文件和过期暂存数据有确定清理路径。

## 12. 验证要点

- 两种格式的有效、部分无效、空包和恶意 ZIP 得到预期结果。
- 预览不修改正式文档，重复确认只执行一次。
- skip、overwrite 和 append 对标题冲突行为稳定。
- 后台执行期间前端离开不取消任务，返回后可查询最终状态。
- 条目失败后统计和剩余条目处理正确。
- 导出内容只包含当前用户数据，ZIP 文件名安全且临时文件被清理。
