# 资产页面与文件存储

## 1. 功能范围

文件上传服务为编辑器粘贴、Markdown 媒体和 `/assets` 资产页面提供统一存储。资产记录描述用户拥有的文件及其引用文档，实际字节存储在本地文件系统或 S3 兼容对象存储。

## 2. 上传流程

上传接口需要 JWT，并接收 multipart 文件：

1. 在读取文件前执行配置的大小限制。
2. 从内容探测 MIME 类型，不能只信任客户端扩展名。
3. 生成包含用户范围和随机部分的存储 Key。
4. 在数据库建立 `pending` 资产。
5. 写入当前存储 Provider。
6. 保存成功后把资产原子标记为 `ready`；失败标记为 `failed` 并尝试删除已写对象。
7. 返回可用于 Markdown 的最终 URL、MIME、大小和文件名。

上传中断不得产生可被其他用户猜测访问的临时文件。对象保存、数据库状态更新或同步删除失败时，
pending/failed 状态和结构化日志必须保留可追踪事实，不能向客户端宣称完整成功。

## 3. 存储 Provider

### 3.1 本地存储

本地存储把 Key 映射到配置目录，并通过 `/api/v1/files/{key}` 读取。处理 Key 时拒绝路径分隔、父目录跳转和非法编码。

响应规则：

- 图片、视频和音频使用内联展示。
- 其他类型使用附件下载。
- 设置正确 `Content-Type` 和 `X-Content-Type-Options: nosniff`。

当前文件读取路由是公开路由，知道 URL 的访问者可以直接请求文件。它不是文档分享权限的延伸，敏感文件不能仅依赖“文档未分享”来保护。

### 3.2 S3 兼容存储

S3 Provider 保存对象 Key，并返回配置的对象 URL。Bucket、Endpoint、凭证和公开读取策略由部署配置控制。数据库仍负责用户资产索引，但对象访问控制取决于存储配置。

## 4. 资产索引

资产表至少记录：

- 用户标识。
- 文件 Key 和 URL。
- 原文件名、MIME 和大小。
- 创建时间。
- `pending|ready|failed` 状态、稳定错误和清理租约。

同一用户和文件 Key 唯一。列表、引用关系和用户可见读取只使用 ready 资产并始终带用户范围。

## 5. 文档资产关系

每次被接受的文档保存都会从正文提取资源 URL：

- 识别本系统 `/api/v1/files/` URL。
- 识别系统允许的绝对资源 URL 和文件扩展。
- 找到当前用户拥有的资产记录。
- 在文档保存事务中替换 `document_assets` 关系。

关系用于资产页展示引用文档，不决定文件字节是否可访问。修改 URL 格式时，上传返回值、渲染器和关系提取器必须同步修改。

## 6. 资产页面

`/assets` 使用 AppPage 和 ResponsiveMasterDetail。`>=768px` 同时显示资产列表和详情，
更窄视口一次只显示一个面板；选择资产进入全宽详情，Back to Assets 返回列表，不把详情
静默放在长列表末尾。

桌面主从面板高度受当前视口约束，列表和详情分别拥有独立的纵向滚动容器并阻止滚动链传播。资产
数量超过一屏时只滚动左侧列表，右侧预览保持在可视区域；详情内容超过一屏时则只滚动右侧。桌面
不能依赖页面级滚动承载任一面板，否则用户选择列表后部的资产时会丢失预览位置。移动端一次只显示
一个面板，继续使用页面纵向滚动，避免在触摸设备上形成没有必要的嵌套滚动区。

列表使用后端现有 `q`、`limit` 和 `offset`：

- 每页请求固定批次，返回不足一批时结束。
- 搜索固定短防抖并从 offset 0 重载。
- 搜索、翻页和详情引用都使用 AbortController/请求序号；旧选择响应不能覆盖新选择。
- 初次错误、追加错误、空资产和搜索无结果分别提供 PageState 与可执行恢复动作。

选择资产后显示：

- 文件预览或类型图标。
- 原始名称、MIME、大小和创建时间。
- 可复制 URL 和 Markdown。
- 使用单一 anchor 的外部打开入口。
- 引用该资产的文档列表和跳转入口。

复制使用带降级路径的共享 clipboard helper；浏览器拒绝时显示 error Toast，不能留下未处理
Promise。References 拥有独立 loading、error、empty 和 Retry。当前页面没有删除资产的完整
业务流程；新增删除功能前必须定义“仍被文档引用”的提示、对象删除失败补偿和孤儿清理策略。

## 7. 编辑器粘贴

编辑器根据上传响应生成：

- 图片 Markdown。
- 视频或音频扩展 Markdown。
- 普通文件链接。

上传占位必须与请求一一对应。用户在等待时继续编辑，成功替换不能使用过期字符索引破坏正文。

## 8. 安全与一致性约束

- 文件大小限制在读取和存储前执行。
- MIME 以内容探测为主，扩展名只用于显示或存储提示。
- 存储 Key 不能由原文件名直接构造。
- 本地文件路由必须防目录穿越并禁止 MIME 嗅探。
- 资产索引与存储写入失败需要可补偿，不能留下不可见永久对象。
- 文档资产关系与正文保存在同一事务。
- 公开文件 URL 的访问模型必须被明确记录；若改为私有，需要同时处理编辑预览和分享访问的签名 URL。
- 资产列表、搜索和引用查询都必须在当前用户范围内；旧响应不能改变新选择。
- 外链不能包含嵌套 Button，复制和 Open 都必须有唯一可访问名称。

超时 pending/failed 由应用级 `AssetCleanupWorker` 收敛。Worker 每小时最多领取 500 条超过一小时的
记录，使用数据库租约避免多实例重复处理；先删除对象，再删除仍非 ready 的记录。对象删除失败时
保存稳定错误并释放租约，ready 资产永不进入该清理路径。

## 9. 验证要点

- 不同 MIME、空文件、超限文件和伪造扩展名得到正确处理。
- 非法 Key、编码绕过和目录穿越被拒绝。
- 本地与 S3 返回的 URL 均可被编辑器和渲染器使用。
- 文档增加、替换和删除资源 URL 后引用关系准确。
- 跨用户无法在资产列表或引用查询中看到文件。
- 上传成功但索引失败时有可观测且可清理的状态。
- 两实例清理同一资产时只有一个获得租约；cleanup 不删除 ready 或仍在上传租约内的对象。
- 超过一个分页批次仍能继续加载；快速搜索和快速切换详情不会串数据。
- clipboard 允许和拒绝、损坏媒体、无引用、多引用和引用失败均有稳定可恢复状态。
- 桌面主从和移动单面板从 `320px` 到宽桌面无 body 横向溢出。
- 资产列表超过一屏时具有实际可滚动高度；滚动到列表底部不会改变页面滚动位置，右侧 Preview
  始终可见，选择底部资产后可以立即查看对应预览。
