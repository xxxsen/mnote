# AI 辅助与语义搜索

## 1. 功能范围

AI 能力包括正文润色、内容生成、摘要、标签建议、语义搜索、相似文档和文档向量索引。AI 是可选增强能力：Provider 未配置、限流或失败时，文档创建、编辑、保存、普通搜索和分享必须继续可用。

## 2. Provider 架构

后端通过统一接口适配 OpenAI、OpenAI-compatible、OpenRouter 和 Gemini 等 Provider。配置把模型实例组织为功能组：

- 文本生成组。
- 文本润色组。
- 摘要组。
- 标签建议组。
- Embedding 组。

每个组可配置多个候选模型。Manager 按配置顺序尝试，处理超时、临时错误和 Provider 不可用。所有外部请求有统一超时和输入长度上限。

Provider Token、Endpoint 和模型配置只存在服务端，不返回浏览器。错误响应不得包含请求头、密钥或完整上游响应。

## 3. 编辑器 AI 操作

### 3.1 润色

用户选择正文或使用当前内容发起润色。结果先进入对比弹窗，按行展示原文与建议，用户明确应用后才修改 CodeMirror。AI 返回不能直接触发远端保存。

### 3.2 生成

生成请求以用户提示和有限上下文为输入。结果在弹窗预览，用户选择插入或替换。插入必须通过 CodeMirror transaction，保留撤销能力和光标位置。

### 3.3 摘要

摘要独立存储，不覆盖正文。用户可以生成、预览并应用摘要。当前后台任务用 `documents.mtime > document_summaries.mtime` 判断摘要过期，并在正文稳定超过配置延迟后重新生成；摘要表没有保存源内容哈希，提交结果前也没有 compare-and-swap。若生成期间正文变化，旧摘要可能以较新的摘要时间写入并暂时被视为最新，这是已知竞态边界，不能把向量任务的哈希保护误认为摘要也已具备。

### 3.4 标签建议

AI 返回候选标签名称，前端与现有标签合并、去重并限制总量。应用时仍走正式标签创建和文档标签更新接口；AI 输出不能直接写数据库，也不能绕过标签所有权。

## 4. 生成结果缓存

文本类 AI 能力使用进程内 LRU/TTL 缓存，Key 由功能类型和规范化输入哈希组成。缓存用于减少相同请求成本，不是持久化事实源：

- Provider 或 Prompt 版本变化时需要纳入 Key 或失效缓存。
- 多实例缓存彼此独立。
- 缓存不得保存认证信息。
- 失败响应不应作为长期成功结果缓存。

## 5. 文档向量状态

正文保存事务不直接调用外部 Embedding。它更新内容哈希并把文档标记为待处理：

- `pending`：需要生成向量。
- `processing`：Worker 已取得租约。
- `complete`：当前内容哈希已有完整向量。
- `failed` 或带重试信息：本次失败，等待退避。

保存事务提交后，后台 Worker 异步处理。状态和内容哈希共同保证旧任务不能覆盖新正文。

## 6. 分块与 Embedding

Worker 读取待处理文档，按标题边界和近似 Token 数切分正文，长块保留有限重叠。块类型区分普通文本、代码或混合内容。

处理流程：

1. 原子取得文档租约并标记 processing。
2. 读取当前内容和哈希。
3. 生成分块；过长代码块可先生成语义摘要。
4. 为每块调用 Embedding Provider。
5. 在事务或锁保护下再次检查文档哈希。
6. 哈希未变化时替换该文档向量并标记完成。
7. 哈希变化时放弃旧结果，让新任务继续处理。

Embedding 结果使用数据库缓存和进程内 LRU，Key 必须包含模型和输入哈希，避免不同模型维度或语义混用。

## 7. 重试与限流

Worker 使用租约防止同一文档被多个执行器长期占用。失败按指数退避，并设置最大退避。Provider 限流时释放或延后任务，不能快速循环打满上游。

服务重启后，超过租约时间的 processing 文档可以重新领取。任何永久失败都应保留可观测错误和下一次可重试时间。

## 8. 语义搜索

语义搜索流程：

1. 使用检索查询模式生成查询向量。
2. 在当前用户的文档分块中执行向量相似度检索。
3. 应用最低相似度阈值和召回上限。
4. 每篇文档只保留有限高分块。
5. 根据块类型权重、命中数量和分数聚合文档得分。
6. 返回文档信息、匹配片段和分数。

数据库查询必须先限制用户范围和有效文档状态，再进行向量排序。不能取全局最近向量后在应用层过滤用户。

## 9. 相似文档

编辑器按当前标题延迟请求相似文档，排除自身并限制结果数量。相似查询是辅助导航，失败或标题为空时不影响编辑器。输入快速变化时应取消或忽略旧响应。

## 10. 安全与成本约束

- 所有 AI 接口需要登录，并受输入长度和上游超时限制；当前 AI 路由没有独立应用层速率中间件，生产成本保护还需要 Provider 配额或网关限流。
- Prompt 中的文档内容属于用户数据，不写入普通日志。
- AI 输出始终视为不可信文本，进入 Markdown 时遵守渲染安全策略。
- AI 建议必须由用户确认后才能改正文、摘要或标签。
- Embedding 只索引当前用户有效文档，并在文档删除或变化时失效。
- Provider 不可用不能阻断正文保存。
- 新增模型时必须保证向量维度与数据库列和既有数据迁移策略一致。

## 11. 验证要点

- Provider 成功、超时、限流和全部失败时返回稳定结果。
- 润色、生成、摘要和标签建议不会在用户确认前修改数据。
- 正文连续保存时，旧哈希向量不会覆盖新内容；摘要竞态按当前已知边界验证并在引入哈希提交保护后补回归验证。
- Worker 崩溃或服务重启后租约可以恢复。
- 语义搜索结果只包含当前用户文档，删除文档不再出现。
- AI 禁用时普通编辑、保存和搜索保持正常。
