# 待办日历页面

## 1. 功能范围

`/todos` 把待办事项按日期展示，支持按日查看、创建、编辑内容、完成切换和删除。桌面使用
可连续滚动的月份日历，移动端使用完整月度日程列表。当前编辑接口不修改到期日期，但创建
表单中的日期可以修改。待办与文档相互独立，按用户和到期日期查询。

## 2. 页面初始化

页面进入后先验证本地会话，再以当前月为中心生成前后月份窗口。每个月固定显示完整周网格，包含相邻月份的补位日期。

初始滚动位置定位到当前月。页面应在布局稳定后定位，避免月份高度尚未计算时出现偏移。

## 3. 无限月份滚动

月列表在用户接近顶部或底部时扩展：

- 接近顶部时前置更早月份。
- 接近底部时追加更晚月份。
- 每次以固定月份批次扩展。
- 前置月份后根据新增内容高度补偿 `scrollTop`，保持用户视野中的日期不跳动。
- 已加载月份范围用于请求待办，范围扩大后只需重新取得该范围内的事实数据。

滚动监听需要节流或防抖；组件卸载时移除监听器。月份 Key 应由年月组成，不能使用数组下标。

## 4. 月视图和日视图

桌面每个日期格使用非交互 `section` 展示当天待办摘要：

- 按完成状态和稳定顺序排列。
- 单元格只展示有限条目，剩余数量以汇总形式提示。
- 新建、查看全部、完成切换和编辑分别使用真实 Button；日期格本身不响应点击。
- 今天、非本月日期和已完成事项使用不同但可访问的视觉状态。

日视图展示完整列表，并提供创建、编辑、完成和删除入口。关闭弹窗后，月视图与日视图必须共享同一数据状态。

小于 `768px` 时不压缩七列月历，而是展示当月每天的日期标题和任务。无任务日期仍有紧凑的
Add task；有任务日期同时提供 Details。每个任务显示 checkbox 语义、Open/Completed 文案
和最多两行内容，不使用 marquee。上月、Today、下月和 New task 始终可见。

## 5. 待办数据

待办包含：

- 用户标识。
- 内容。
- 到期日期，格式为 `YYYY-MM-DD`。
- 完成状态。
- 创建和更新时间。

日期按业务日处理，不应在浏览器与服务器之间按 UTC 时间戳来回转换，否则时区可能把事项移动到相邻日期。接口的范围查询使用开始和结束日期。

## 6. 创建和编辑

- 页面 New 默认今天，日期行 New 默认对应日期；创建表单允许在提交前修改日期。
- 内容在提交前去除首尾空白，并满足后端长度上限。
- 编辑只修改内容；到期日期在创建后保持不变，若未来支持改期，需要扩展前后端 DTO 和日期范围状态同步。
- 保存期间禁用重复提交。
- 成功后用服务端返回值替换或插入本地项。
- 失败时保持表单和用户输入，便于重试。

后端始终以用户 ID 和待办 ID 更新目标记录。当前内容更新不会移动日期，因此月视图只需替换正文和更新时间。

## 7. 完成切换

完成状态可采用乐观更新：

1. 先切换本地视觉状态。
2. 发送 toggle 接口。
3. 成功后以响应校准。
4. 失败时恢复原状态并提示。

连续快速点击需要串行或按操作序号处理，旧响应不能覆盖最终用户意图。

## 8. 删除

删除前需要确认。成功后从月视图和打开的日视图同时移除。后端删除条件必须包含用户 ID 和待办 ID；删除不存在或不属于当前用户的记录返回统一未找到或无权限错误。

## 9. 不可破坏的约束

- 到期日是无时区业务日期，不得隐式转换为 UTC 日期。
- 无限滚动前置月份时必须保持视觉位置。
- 月视图和日视图使用同一事实状态。
- 所有写操作防重复并处理失败回滚。
- 待办查询和写入严格按用户隔离。
- 大月份范围不能为每个日期单独请求，应使用范围查询。
- 手机不得渲染压缩桌面七列月历；触摸和键盘不得依赖 hover。
- 页面、日详情和写入 Dialog 使用同一待办事实状态。

## 10. 验证要点

- 月首、月末、闰年、跨年和不同时区下日期正确。
- 向上和向下连续加载月份时没有跳动、重复或缺月。
- 创建、内容编辑、完成切换和删除后两种视图一致。
- 快速重复切换完成状态最终与最后一次操作一致。
- 请求失败后乐观状态回滚，表单输入可重试。
- 大范围待办仍通过有限请求加载。
- `320px` 到宽桌面无 body 横向溢出；手机可创建今天或任意日期任务并完成完整 CRUD。
- 日期、Add task、Details、checkbox、Edit 和 Delete 都能通过 Tab、Enter 或 Space 使用。
- 长文本、空月、单日大量任务和跨月任务在两种布局中均保持可读。
