# 标签页面与标签关系

## 1. 功能范围

标签能力贯穿 `/tags`、文档库侧栏、编辑器和模板。标签属于用户，文档与标签是多对多关系。标签页面负责全量管理，其他页面只负责在各自上下文中筛选、置顶或选择标签。

## 2. 数据模型

- 标签包含用户标识、名称、置顶状态和时间字段。
- 同一用户下名称唯一，不同用户可以使用相同名称。
- 文档标签关系以文档 ID 和标签 ID 唯一。
- 模板保存默认标签 ID，创建文档时再校验这些标签仍属于当前用户。

所有标签查询和写入都必须携带当前用户范围。只校验标签 ID 存在不足以防止跨用户关联。

## 3. 标签管理页面

`/tags` 以汇总列表展示标签名称、文档数量和状态：

- 初次加载固定批次。
- 滚动接近底部时加载下一页。
- 搜索条件改变时重新从第一页加载。
- 删除前弹出确认，成功后移除标签并更新统计。
- 从其他页面返回时保留安全的返回路径，不能接受任意外部跳转地址。

删除标签不会删除文档。后端在事务中先删除文档标签关系，再删除标签本身。

## 4. 文档库侧栏

文档库侧栏以独立分页加载标签，并支持：

- 选择标签筛选文档。
- 置顶或取消置顶。
- 显示更多标签。

标签置顶只改变标签排序。请求失败时页面应恢复旧状态；标签被删除后，当前筛选必须清空并重新加载文档。

## 5. 编辑器标签

编辑器展示当前文档标签，并提供搜索、创建和移除。页面对标签名称进行输入约束，并限制一次选择数量，避免标签区域失控。

更新流程：

1. 前端得到完整目标标签 ID 列表。
2. 后端应验证所有 ID 属于当前用户。当前 `UpdateTags` 路径只校验文档所有权，尚未逐个验证标签 ID；数据库关系表也没有外键，因此直接构造请求可能写入不存在或属于其他用户的标签 ID，这是已知数据完整性缺口。
3. 在事务中替换该文档的标签关系；完成逐 ID 所有权校验后才能写入。
4. 返回最终标签列表，前端以响应校准。

替换语义意味着漏传一个已有标签会删除它。调用方必须提交完整目标集合，而不是只提交增量。

## 6. 创建与批量查询

- 创建接口对名称去空白并执行同用户唯一性检查。
- 并发创建同名标签时，以数据库唯一约束为最终裁决，并返回归一化冲突错误。
- 批量 ID 查询用于恢复选择状态，仍需过滤当前用户之外的 ID。
- 汇总接口把标签和文档计数一次返回，避免页面逐标签查询。

## 7. 正文保存的交互边界

文档正文保存和标签更新是不同用户操作，但后端文档更新 DTO 也可能包含标签列表。维护时必须明确三种状态：

- 未提供标签字段：保持原标签。
- 提供空列表：清空全部标签。
- 提供非空列表：替换为目标集合。

如果 DTO 无法区分“未提供”和“空列表”，正文保存调用可能意外清空标签。新增接口或重构保存模型时必须保留这一区分。

## 8. 不可破坏的约束

- 标签名称唯一范围是单个用户。
- 文档只能关联同一用户拥有的标签。
- 删除标签不删除文档。
- 文档标签更新必须在事务中执行完整替换。
- 页面分页、搜索和置顶状态不能互相污染。
- 模板中的失效标签在创建文档时被忽略或明确报错，不能形成跨用户关系。

## 9. 验证要点

- 同用户重复名称被拒绝，不同用户同名成功。
- 标签分页、搜索、滚动加载不会重复或漏项。
- 删除有文档关系的标签后文档仍存在，关系和统计正确。
- 编辑器添加、移除和清空标签后刷新结果一致。
- 跨用户标签 ID 无法用于文档或模板。
- 正文保存不携带标签字段时不会意外改变标签。
