# 编辑器与 Markdown 开发测试页面

## 1. 功能范围

`/test-editor` 和 `/test-markdown` 是用于隔离验证复杂前端组件的开发页面。它们不是用户数据页面，不应承担正式业务流程或成为其他页面依赖。

## 2. 编辑器测试页

`/test-editor` 使用固定示例 Markdown 加载独立 CodeMirror，当前用于验证初始化、输入、Markdown 语法解析、行号、折叠、换行和主题切换。主题偏好复用正式编辑器的本地存储，但页面不加载文档、不调用 API，也不具备正式编辑器的工具栏、保存队列、草稿、文件粘贴和关联功能。

因此该页面只适合验证底层编辑器和主题，不得用它代替 `/docs/[id]` 的保存、输入法、快捷菜单和竞态验证。

## 3. Markdown 测试页

`/test-markdown` 直接加载共享 `MarkdownPreview`，当前固定样例覆盖标题、受控 `span`/`font` 样式、四类提示块，以及 Lua、C 的可运行代码。它不读取账户或文档数据。

当前样例没有覆盖 GFM 表格、任务列表、公式、目录、重复标题、内部链接、媒体、Mermaid、JavaScript、Python 和 Go 运行时；这些能力仍由组件测试和正式页面验证。扩充样例时应保持确定性，不依赖私有外部数据；需要 CDN 运行时的示例必须对离线失败有明确展示。

## 4. 与自动化测试的关系

开发测试页用于人工探索和浏览器自动化挂载，不替代组件单元测试和正式页面端到端测试。公共组件变更应先在隔离页定位，再验证真实编辑器和分享页面的数据流。

测试页不得包含专门让组件“看起来通过”的分支；组件在测试页和正式页面使用相同实现。

## 5. 生产暴露策略

这些路由不包含管理权限，不得展示环境变量、Token、日志或用户私有数据。生产环境可通过构建开关、路由中间件或反向代理限制访问。

如果保持公开可访问：

- 页面明确标记为开发验证。
- 不提供真实数据写入口。
- 不自动执行示例代码。
- 不暴露依赖版本、内部地址或调试堆栈。

移除生产路由时，自动化测试应直接挂载组件或在测试构建中启用，不能让生产功能依赖测试页存在。

## 6. 维护规则

- 新增 Markdown 语法或编辑器交互时补充最小代表性示例。
- 删除功能时同步删除失效示例。
- 示例只描述稳定能力，不记录临时问题编号或开发进度。
- 页面不使用生产账户或固定敏感凭据。
- 调试输出和临时开关不得提交。

## 7. 验证要点

- 两个页面可独立打开且不要求已有用户数据。
- 编辑器组件在输入法、快捷键和大文本下可操作。
- Markdown 示例局部失败不会导致整页崩溃。
- 页面不发起意外写请求、不泄露令牌和配置。
- 生产限制策略与部署配置一致。
