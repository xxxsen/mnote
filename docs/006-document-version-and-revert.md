# 文档版本与恢复页面

## 1. 功能范围

文档版本用于保存每次被后端接受的正文修订，并在 `/docs/[id]/revert` 页面进行当前版本与历史版本对比和恢复。版本是内容保存事务的一部分，不是独立的客户端快照。

## 2. 版本生成

创建文档时建立初始修订。后续正文保存只有在 `save_seq` 大于文档当前修订号时才被接受：

1. 事务锁定文档行。
2. 比较保存序号和当前内容修订号。
3. 接受后更新正文、标题和修订号。
4. 以相同修订号写入历史版本。
5. 同一事务更新关联关系和待处理状态。

旧序号请求返回未接受及当前修订号，不产生重复历史版本。版本保留数量由服务端配置控制，超出后删除最旧版本。

## 3. 历史列表与详情

编辑器从版本列表接口获取修订元数据，恢复页再按版本号读取正文和标题。所有接口都必须验证文档属于当前用户，不能只凭版本记录 ID 查询。

URL 可以携带版本参数。页面需处理：

- 文档不存在或无权访问。
- 版本不存在或已被保留策略清理。
- 参数不是有效整数。
- 当前版本与所选版本相同。

## 4. 差异计算

恢复页按行比较当前内容和历史内容，并展示左右两侧差异：

- 标记新增、删除和未变行。
- 单独显示标题是否变化。
- 提供上一处和下一处差异导航。
- 支持键盘方向键导航。
- 空文档、末尾换行和大段连续变更仍保持行号对应。

当前差异算法基于行级最长公共子序列，时间和内存复杂度随两份文档行数乘积增长。大型文档应设置降级阈值或改用分段算法，避免页面冻结。

## 5. 恢复语义

恢复不是回退数据库事务，也不删除恢复点之后的版本。正确语义是“把历史标题和正文作为一次新的保存”：

1. 页面先加载当前文档修订号。
2. 用户确认恢复。
3. 请求携带历史标题、历史正文和大于当前修订号的新 `save_seq`。
4. 后端按普通文档保存事务创建一个新版本。
5. 成功后回到编辑器，并以服务端响应校准内容和修订号。

因此恢复后仍可再次查看恢复前的版本。

## 6. 当前调用契约注意事项

文档更新接口要求正数 `save_seq`。当前恢复页只提交历史标题和正文，没有携带 `save_seq`，因此会被现有后端以参数错误拒绝；这是当前恢复功能的已知实现缺口。修复时应读取或重新取得最新 `content_revision`，按普通保存协议提交更大的序号，并处理未接受响应，不能在后端为恢复路径放开无序号写入，否则会重新引入旧写覆盖新写问题。

## 7. 并发处理

用户打开恢复页后，文档可能在另一标签页继续编辑。确认恢复前应重新取得当前修订号，或由后端接受一个显式基准修订并检测冲突。不能沿用进入页面时的旧序号强行覆盖。

若后端返回未接受：

- 页面不得显示恢复成功。
- 应提示内容已变化并重新加载差异。
- 用户可基于新的当前版本再次确认。

## 8. 不可破坏的约束

- 每个被接受的正文修订对应一个历史版本。
- 未接受的旧保存不生成版本。
- 恢复产生新版本，不重写或删除历史。
- 恢复必须进入与编辑器保存相同的并发控制和关系重建流程。
- 版本查询必须同时校验文档所有权。
- 大文档差异计算不能无限占用主线程。

## 9. 验证要点

- 连续保存产生单调递增且内容正确的版本。
- 重复或乱序保存不增加版本。
- 标题、正文、空行和末尾换行差异显示正确。
- 恢复后正文等于所选历史内容，且新增一个恢复版本。
- 恢复页打开期间发生并发保存时，不会静默覆盖新内容。
- 已清理版本、无权访问和无效参数均显示稳定错误状态。
