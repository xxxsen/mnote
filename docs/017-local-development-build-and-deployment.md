# 本地开发、构建与部署

## 1. 功能范围

工程提供 Makefile、开发启动脚本、Docker Compose、前后端构建命令和质量检查。开发环境与生产环境使用不同端口和配置，但前端 API 地址必须始终指向同一轮启动的后端。

## 2. `make dev`

`make dev` 是本地全栈快速启动入口，默认端口：

- 前端：`3090`。
- 后端：`8850`。
- PostgreSQL：`15432`。

启动逻辑为当前工作区创建隔离的 Compose 项目和数据库数据目录，生成开发后端配置，启动数据库、Go 服务和 Next.js 开发服务器。脚本在退出时清理本轮子进程和容器，避免遗留端口占用。

前端通过环境变量得到 `http://localhost:8850/api/v1` 等后端基址，后端 CORS 同时允许 `http://localhost:3090`。端口覆盖时这两个值必须由同一组变量推导，不能只改变监听端口。

## 3. 端口和环境覆盖

开发脚本允许用环境变量覆盖前端、后端和数据库端口。覆盖要求：

- 端口值直接传给数据库、Go 和 Next.js 进程；当前脚本不预先探测格式或占用，非法值和冲突由对应进程启动失败暴露。
- 生成的后端监听地址使用新后端端口。
- 前端公开 API 基址使用新后端端口。
- 后端 CORS 使用新前端端口。
- 默认开发配置禁用 OAuth；使用自定义 OAuth 配置时，调用者必须把 Provider 回调地址与覆盖后的前端端口保持一致。
- 数据库 DSN 使用新数据库端口。

不得把开发生成的凭据、数据目录或配置提交到版本库。

## 4. 开发配置

快速启动配置面向本地验证：

- 使用独立 PostgreSQL 数据。
- 提供可重复使用的本地测试账户或注册路径。
- 文件使用本地存储目录。
- AI 默认可关闭，避免启动依赖外部密钥。
- 日志输出到当前终端，便于定位前后端启动失败。

脚本先等待数据库通过 `pg_isready`，再启动 `go run ./cmd/mnote`。只有后端端口开始接受连接后才启动 Next.js，避免页面已可访问但 API 尚未就绪。后端在就绪前退出或超过等待期限时，启动脚本直接失败。任一关键进程退出时 `wait -n` 结束主脚本，退出 trap 清理本轮记录的前后端进程并停止开发数据库。

## 5. 常用检查

后端：

```bash
go fmt ./...
go mod tidy
go test ./...
make lint-go
make test-coverage
```

后端整体覆盖率门槛由 Makefile 管理，当前为 80%。

前端：

```bash
cd web
npm run lint
npx tsc --noEmit
npm run test:coverage
npm run build
```

前端整体覆盖率门槛当前为 30%，测试应优先覆盖登录、文档保存、草稿恢复、分享权限、导入确认等关键路径，而不是为提高数字测试无业务价值的样板代码。

## 6. 前端开发与构建

Next.js 开发服务器读取公开 API 环境变量。变量值会进入浏览器包，不能包含密钥。生产构建必须使用部署环境的后端公开地址。

`npm run build` 同时验证 App Router、服务端与客户端边界、类型和静态生成。修改路由、Layout、Next 配置或环境变量时必须运行。

## 7. 后端开发与构建

Go 服务从配置文件和环境读取数据库、JWT、邮件、存储、AI、CORS 和任务配置。启动顺序为：

1. 解析并校验配置。
2. 连接数据库并执行迁移。
3. 初始化 Repository、Service、Provider 和存储。
4. 注册路由和中间件。
5. 启动后台调度。
6. 监听 HTTP。

任何必需依赖初始化失败应退出；可选 AI Provider 失败按配置降级。

## 8. Docker 部署

生产 Compose 编排 PostgreSQL、后端、前端和反向代理。容器内部可继续使用服务端口，外部端口由反向代理或 Compose 映射。开发默认 `3090/8850` 不要求替换生产内部端口。

生产部署必须持久化：

- PostgreSQL 数据。
- 本地文件存储目录，若未使用 S3。
- 必需配置和密钥。

升级前备份数据库和文件。新版本先执行兼容迁移，再切换流量。不得在多个不兼容版本之间长期混跑。

## 9. 反向代理

反向代理负责：

- 前端页面流量。
- `/api/` 到后端。
- 上传大小和请求超时。
- HTTPS 和安全响应头。
- 正确传递客户端地址。

公开分享和 OAuth 回调需要稳定外部基址。修改域名或协议时同步更新 CORS、OAuth Provider 配置和页面生成链接。

## 10. 不可破坏的约束

- `make dev` 的前端 API 基址与本轮后端端口始终一致。
- Next.js 只在后端完成初始化并开始监听后启动。
- 开发实例使用隔离项目名和数据，退出时只清理自身资源。
- 公开前端环境变量不能包含服务端密钥。
- 生产数据和文件使用持久卷或对象存储。
- 数据库迁移成功前后端不能接收业务流量。
- 覆盖率门槛关注关键路径，不能用跳过失败测试或排除核心目录规避。

## 11. 验证要点

- 默认执行 `make dev` 后，`3090` 页面可以请求 `8850` 后端。
- 覆盖三个端口后，API、CORS、数据库和 OAuth 回调仍使用覆盖值。
- 退出开发脚本后没有遗留进程、容器或端口。
- 空库和已有库均可启动。
- 前后端生产构建通过，容器健康检查正常。
- 反向代理下登录、上传、分享和 OAuth 回调使用正确外部地址。
